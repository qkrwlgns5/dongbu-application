# dongbu-application

동부교육지원청 학교스포츠클럽대회 참가 신청 웹 애플리케이션입니다.

운영 주소: <https://dongbu-application.qkrwlgns5.workers.dev>

## 주요 기능

- 새 대회는 종목·종별 없이 비공개로 생성되며, 종목 관리에서 필요한 항목을 직접 추가
- 종목 그림 선택: 전국학교스포츠클럽축전 19개 종목의 공·상징, 공통 그림, 종목명에 맞춘 자동 선택
- 73개 초등학교·42개 중학교의 기관번호 로그인(한글·영문 키보드 지원)
- 새 대회 추가 시 초등학교·중학교 대상 선택, 여러 대회 동시 공개와 교사 로그인 전 대회 선택
- 관리자 신청 현황의 초등/중등 탭, 학교급별 대상·신청 집계와 엑셀 내보내기
- 학교 관리에서 신설 학교 등록, 기존 학교 기관번호 수정과 중복 확인
- 배구·3x3 농구·피구 및 남중부·여중부 참가 신청
- 종목별 `학교 전체 최대 팀 수`와 `한 종별 최대 팀 수`를 분리해 검증
- 초기 대회의 팀 수 설정: 배구 전체 2팀·한 종별 2팀, 3x3 농구와 피구 전체 2팀·한 종별 1팀 (이후 새 대회에는 자동 등록하지 않음)
- 저장 후 재로그인 시 기존 제출 내용 불러오기
- 신청 완료·참가 신청 없음·미신청 구분
- 관리자 학년도·대회명·신청 기간·종목 및 두 단계 팀 수 한도 관리
- 청록·화이트 프론트엔드, 학교 검색과 참가 신청 실시간 요약
- 대회별 로그인 안내 카드 문구 편집·미리보기 및 카드 중앙정렬
- 대회별 메인 상단 로고 문자·기관명·보조 문구·영문 문구·두 줄 제목 편집 및 미리보기
- 교사 화면과 관리자 화면의 로고·기관명·보조 문구 공통 적용: 관리자는 조회 대회, 로그인 전에는 공개 기본 대회 기준으로 표시
- 관리자 아이디·비밀번호 변경 및 전체 관리자 세션 만료
- 모든 학교의 종목·종별·팀 수 결과 종합
- 교사 신청 화면에서 종목별 신청 학교 조회: 전체·종별 필터, 학교별 팀 수, 우리 학교 표시

## 새 대회와 종목 그림

종목 목록 기준: [학교체육진흥회 학교스포츠클럽포털 · 제19회 전국학교스포츠클럽 축전](https://schoolsportsclub.or.kr/games/result/clbr/info), 2026-09-14 확인. 남고 배구·여고 배드민턴처럼 별도 운영되는 종별은 해당 종목의 그림을 함께 사용합니다.

**새 대회 추가**는 기존 대회·신청을 유지하면서 종목과 종별이 하나도 없는 비공개 대회를 만듭니다. 생성 직후 **종목 관리**로 이동하여 필요한 종목과 종별을 직접 추가합니다. 종목을 추가하는 입력창에는 선택한 학교급에 맞는 종별을 제안하지만, **종목 추가**를 누르기 전에는 저장되지 않습니다. 이미 만들어진 대회의 종목·종별·팀 수·신청은 삭제하거나 초기화하지 않습니다.

**종목 관리 → 새 종목 추가 또는 기존 종목 수정 → 종목 그림 선택**에서 원하는 공·상징을 선택하고 저장합니다. 선택한 그림은 종목 관리 목록과 관리자 결과 종합의 종목 배너에 함께 표시됩니다. 교사 화면에서 이전에 제거한 문자 배지는 다시 만들지 않습니다.

2026년 전국학교스포츠클럽축전 안내의 19개 종목인 3x3 농구·넷볼·농구·배구·배드민턴·스포츠스태킹·야구·육상·족구·줄넘기·축구·치어리딩·킨볼·탁구·티볼·풋살·플라잉디스크·플로어볼·피구와 공통 트로피 그림을 제공합니다. 그림은 서비스에 포함한 자체 SVG이며 외부 이미지 주소를 저장하거나 불러오지 않습니다.

**종목명에 맞춰 자동**은 이름에 맞는 그림을 표시하고 알 수 없는 종목은 공통 그림으로 표시합니다. 직접 선택한 그림은 이름·종별·팀 수 변경이나 활성화 전환 뒤에도 유지됩니다. 종목별 설정은 서로 독립적이며 기존 종목에는 자동 표시를 적용해 기존 데이터를 변경하지 않습니다.

## 기술 구성

- vinext + React
- Cloudflare Worker Static Assets
- Cloudflare D1 + Drizzle 마이그레이션
- HttpOnly / SameSite 세션 쿠키
- PBKDF2-SHA-256 + 서버 pepper를 사용한 학교 기관번호 검증
- D1에 PBKDF2-SHA-256 해시만 저장하는 관리자 계정 인증

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```bash
npm install
cp .dev.vars.example .dev.vars
npm run db:local
npm run dev
```

`.dev.vars`에는 다음 비밀값을 설정합니다. 이 파일은 Git에 포함되지 않습니다.

- `ADMIN_USERNAME`
- `ADMIN_PASSWORD`
- `SCHOOL_PASSWORD_PEPPER`

`ADMIN_USERNAME`과 `ADMIN_PASSWORD`는 `admin_credentials` 행이 없을 때 최초 관리자 계정을 만드는 부트스트랩 값입니다. 최초 로그인에 성공하면 관리자 비밀번호는 서버 pepper를 적용한 해시로 D1에 저장되며, 이후에는 D1 계정만 인증에 사용되고 환경 변수 계정으로 재시도하지 않습니다.

## 검증

```bash
npm run lint
npm run typecheck
npm test
```

`npm test`는 실제 API 처리기를 독립적인 메모리 SQLite에 연결하여 카드·상단 문구 권한·저장·대회 분리, 학교 로그인·신청 재조회·팀 수 한도·기간 제한을 검증합니다. 운영 데이터나 운영 비밀번호는 테스트에 사용하지 않습니다.

## 교사용 신청 학교 현황

학교 로그인 후 각 종목 카드의 **신청 학교 보기**에서 현재 대회의 저장 완료된 신청을 조회합니다. 전체에서는 같은 학교의 여러 종별을 1개교로 묶고, 종별 필터에서는 해당 종별 학교 수·팀 수를 표시합니다. 현재 편집 중인 미저장 선택은 집계에 포함하지 않습니다. 창을 열 때와 **현황 새로고침**을 누를 때 최신 저장값을 조회하며, 모달 안에서만 스크롤하고 닫으면 기존 위치·초점을 복원합니다.

`GET /api/school/participants`는 학교 세션에 연결된 대회·신청 기간·학교 활성 상태·대상 학교급을 검증합니다. 쿼리로 세션과 다른 대회를 지정할 수 없으며, 활성 학교·종목·종별의 참가 신청만 학교명·종별·팀 수로 반환합니다. 계정 정보, 다른 학교의 수정 이력·미신청 상태, 관리자 데이터는 반환하지 않습니다.

## 여러 대회 운영·학교 관리

관리자 → **대회·기간 설정**에서 **새 대회 추가** 시 초등학교·중학교 중 하나 또는 둘 모두를 선택합니다. 새 대회는 비공개로 생성됩니다. 설정 확인 후 **교사 화면에 공개**하면 다른 공개 대회를 유지한 채 함께 운영합니다. 두 개 이상의 대회가 공개되면 교사는 로그인 화면에서 대회를 선택하고 해당 대회에 참가 신청합니다. 기존에 로그인한 교사는 **다른 대회 선택**으로 이동하며, 이미 저장한 신청은 대회별로 유지됩니다. 날짜를 설정하는 것과 공개하는 것은 별도입니다.

학교별 신청 현황은 초등/중등 탭으로 분리되며 집계·종별·학교 목록은 선택한 대회의 대상 학교급을 따릅니다. 참가 학교 조회와 엑셀 내보내기도 같은 대회 범위로 제한됩니다. 이미 종료된 대회는 이후 신설 학교를 추가해도 대상 학교 수가 바뀌지 않습니다.

관리자 → **학교 관리**에서 학교급·학교명·기관번호로 새 학교를 등록할 수 있습니다. 기존 학교는 **기관번호 수정**에서 새 번호와 확인 번호를 입력합니다. 번호가 변경되면 해당 학교의 모든 대회 로그인만 만료되며 학교 ID·학교명·순번·기존 신청은 유지됩니다. 같은 번호를 다시 입력하면 변경 없이 기존 로그인을 유지합니다. 기관번호 원문은 저장·목록 표시·감사로그에 기록하지 않습니다. 중복 방지용 HMAC 지문은 학교 ID와 분리해 저장하며, 변경·해당 학교 세션 만료·감사 기록은 원자적으로 처리합니다.

수요조사 사이트와 참가신청 사이트의 데이터베이스·비밀값·계정·신청 내역은 서로 독립적입니다. 초등학교 명단은 기존에 제공된 기관번호 자료에서 정리한 동일 73개교를 사용하되, 참가신청 사이트의 기존 pepper로 새 salt/hash를 생성했습니다. 수요조사 응답이나 대회 설정은 복사하지 않습니다. `0009`~`0012`는 기존 신청 사이트의 `0000`~`0008` 뒤에 추가하며, 기존 학교 기관번호·신청·대회명·기간·로고 설정을 변경하지 않습니다.

로컬 기능 시안은 무시되는 `work/participants-preview/`의 예시 데이터로 운영 환경과 분리됩니다. 시안은 `node work/participants-preview/server.mjs`로 열며 실제 운영 기록을 읽거나 쓰지 않습니다.

## 메인페이지 상단 로고·제목 수정

관리자 → **대회·기간 설정** → **메인페이지 상단 로고·제목**에서 로고 문자(한글·영문·숫자 1~3자), 기관명, 기관명 아래 문구, 학년도 배지 옆 영문·안내 문구, 제목 첫째 줄·둘째 줄을 수정합니다. 아래 미리보기에서 확인 후 **상단 로고·제목 저장**을 누릅니다. **기본 문구 불러오기**는 저장하기 전까지 미리보기에만 적용됩니다. 학년도 배지는 위쪽 **대회 정보·신청 기간**의 학년도와 연동되며 따로 중복 저장하지 않습니다.

저장한 로고·기관명·기관명 아래 문구는 관리자와 교사 화면이 동일하게 사용합니다. 관리자는 현재 조회 대회, 교사는 선택하거나 로그인한 대회 기준으로 표시합니다. 저장 후 관리자 화면은 즉시 최신 설정을 읽으며, 이미 열려 있는 교사 화면은 새로고침하면 반영됩니다. 아래 문구를 비워 저장하면 양쪽 모두 숨깁니다. 관리자 로그인 전에는 공개 기본 대회의 브랜드만 표시하고, 비공개 대회의 설정은 노출하지 않습니다. 모바일에서도 브랜드와 메뉴를 서로 다른 행에 배치합니다.

`0007_page_header_copy.sql`은 `tournaments.header_copy` 열만 기본값 `'{}'`로 추가합니다. 기존 카드·대회·학교·신청 기록은 변경하지 않으며, 코드 배포 전에 마이그레이션을 먼저 적용합니다. 헤더 저장은 관리자 인증·동일 출처 검사·허용 필드/문자열 검증을 거쳐 감사 로그와 함께 기록됩니다.

## 메인페이지 안내 카드 수정

관리자 → **대회·기간 설정** → **메인페이지 안내 카드 문구**에서 큰 제목, 제목 아래 문구, 학년도 안내, 참가 대상, 하단 안내를 수정합니다. 입력 중 오른쪽 미리보기에서 확인하고 **안내 카드 문구 저장**을 누릅니다. 각 대회에 독립적으로 저장되며 신청 기간·종목·학교 수는 실제 설정에서 자동 표시됩니다. 빈 문구는 숨겨지고 제목과 설명의 직접 입력한 줄바꿈은 유지됩니다.

`0006_event_card_copy.sql`은 기존 대회 테이블에 기본값이 빈 설정 객체인 `card_copy` 열만 추가합니다. 배포 시 이 마이그레이션을 먼저 적용한 뒤 새 Worker를 배포합니다. 구 버전 Worker와 기존 신청 기록에 호환되며 기존 대회 정보 저장 요청은 카드 문구를 덮어쓰지 않습니다.

## 로고 PNG 호환성 확인

로고 원본은 PNG·JPG·WebP 최대 10MB까지 선택할 수 있으며, 브라우저에서 비율을 유지해 최대 512px PNG로 변환합니다. Safari가 새 canvas PNG에 자동으로 붙이는 EXIF 부가정보(`eXIf`)만 업로드 전에 제거하고, 이미지 픽셀·투명도·색상 정보는 유지합니다. 서버는 CRC·크기·압축 픽셀을 계속 검사하며, 표준 ICC 색상 프로필은 별도의 압축 해제 상한으로 검증합니다.

`tests/logo-image.test.mjs`에는 Safari에서 실제 생성한 작은 합성 PNG로 회귀 테스트가 포함되어 있습니다. 수요조사·참가신청 격리 브라우저 검증은 참가신청 저장소의 `node tests/logo-browser-server.mjs 4319`로 실행합니다. 메모리 SQLite/R2만 사용하며 운영 데이터·계정·원본 파일은 변경하지 않습니다.

## Cloudflare 배포

1. `dongbu-application-db` D1 데이터베이스를 만듭니다.
2. `wrangler.jsonc`의 `database_id`를 실제 D1 ID로 변경합니다.
3. D1 마이그레이션을 적용합니다.

```bash
npx wrangler d1 migrations apply dongbu-application-db --remote
```

4. Worker Secret을 등록합니다.

```bash
npx wrangler secret put ADMIN_USERNAME
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SCHOOL_PASSWORD_PEPPER
```

5. 빌드 후 생성된 Worker 설정으로 배포합니다.

```bash
npm run build
npx wrangler deploy --config dist/server/wrangler.json
```

GitHub 자동 배포는 `main` 브랜치에서 빌드 명령 `npm ci && npm run build`, 배포 명령 `npx wrangler deploy --config dist/server/wrangler.json`을 사용합니다. D1 마이그레이션은 코드 배포와 별도로 적용해야 합니다.

## 보안 주의사항

- 학교 기관번호 원문은 코드·Git 기록·D1에 저장하지 않습니다.
- `.dev.vars`, Cloudflare API 토큰, 관리자 비밀번호, pepper를 커밋하지 마세요.
- 신청 기간 판정과 학교·관리자 권한 검사는 모두 서버에서 수행됩니다.
- 참가 신청은 각 종별 한도를 먼저 확인한 뒤, 해당 종목의 학교 전체 합계 한도를 다시 확인합니다.
- 관리자 계정 변경 시 기존 관리자 세션은 모두 만료됩니다. 계정 복구를 위해 D1의 `admin_credentials`를 초기화해야 하는 경우에는 먼저 백업하고, 새 부트스트랩 비밀값을 설정한 뒤 제한된 유지보수 창에서만 수행하세요.
